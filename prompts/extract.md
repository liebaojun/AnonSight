# 任务：把一节论文原文，变成「思想图 + 导读」的 JSON

你在给一个论文精读平台做**后台抽取**。给你的是一节论文的原文（可能带 `[第 N 页]` 分页标记），
你要输出这一节的**导读**和**若干张思想图**。

> 你的输出会被一个**硬校验器**逐条检查，不过就整份打回。所以：格式一个字符都不能错，
> 引文必须**逐字**来自给你的原文。

---

## 一、抽取铁律（违反 = 返工）

1. **先通读整节定框架，再逐句挂关系**。
   - 第一遍：从**枚举句、定义句**里抽"谁包含谁、谁是谁的一员"（`origin: structural`）
   - 第二遍：从**叙述句**里抽因果/调控（`origin: sentence`）
   - ⚠ 反过来（一上来就逐句抽）必定漏掉「CD3ε 属于 CD3 四链」这类**原文没明说但常识成立的结构关系**，图会碎成一堆孤岛
2. **结构关系可以补全，机制关系只认原文**。
   - ✅ 可以：CD3ε 属于四链、四链被 TCR 关联 → 画 CD3ε 与 TCR 的结构边
   - ❌ 不行：**A 抑制 B、B 促进 C，推不出 A 抑制 C**（中间可能有反向通路）。推出来的是**错误的生物学结论**
   - 拿不准就标 `origin: inferred`，别标 `sentence`
3. **每一条边、每一个节点都必须给证据**：`{"page": 页码, "quote": "原文里的那句话"}`
   - `quote` 必须能在给你的原文里**原样找到**（一个字都不能改：标点、空格、大小写都要一致）
   - **做不到溯源的关系，宁可不画**。把"促进"标成"抑制"比不标更糟
4. **先看"这节在讲什么"，再定图型**——一张图只回答一个问题。
   四种图**各有各的用场**，判据就是下面这一张表，**不许按习惯挑、更不许一律给概念网**：

   | 这一节的内容在讲什么 | 该用什么图 |
   |---|---|
   | 一堆东西 + 它们之间的关系（讲道理、铺概念、谁包含谁） | **概念网** `concept-map`（气泡网） |
   | 有先后、有分支的过程 · 信号级联 · 实验流程 · 处理步骤 | **流程图** `flow`（方框箭头） |
   | 这东西长什么样 · 结构域怎么排 · 构建体/载体怎么设计 | **模式图** `domain`（横条+方块） |
   | 同类之间差在哪一格 · 突变体×表型 · 方案/条件对比 | **对照表** `matrix` |
   | 有反馈回路 / 自我调节（A 管 B、B 又反过来管 A） | 流程图**不许成环**（校验器已拦）——拆成两条边，别连一条回到起点的箭头 |

   - **一节里凡是有"先后、分支、级联、流程"的内容，就得有 `flow`**；凡讲到"长什么样、
     怎么搭出来的"，就得有 `domain`；凡"几个东西并排比"，就得有 `matrix`。
     概念网只是四种里的一种——它是"这节在铺概念"时的选择，**不是默认**。
   - **先在心里把这一节分成几个"意思块"**——哪几段在讲同一件事、话题在哪里转的。
     文章**哪怕没有小标题**，也总是几段讲完一件事再换下一件；
     **全是同一件事黏在一起的整节其实很少见**。分图就按这个分，**不按字数、不按页数**：
     * **只分得出一块** → 就出**一张**，图型按上面那张表挑最贴这个内容的。
     * **分得出多块** → 出「**1 张概览 + 每块 1 张**」：
       - **概览必须是"覆盖全节的概览概念网"**——把这节的主要角色和它们的关系网罗进来，
         它是用户进这一节的**地图**。⚠ **绝对不许用某个子话题的概念网冒充概览**
         （比如一节讲完设计又讲信号又讲体内实验，概览却只画了信号那一块）。
       - 后面几张各管一个意思块，图型按**那一块**的内容挑（过程→`flow`／结构→`domain`／对比→`matrix`）。
     - **长度不是分图的理由**：1.4 万字里有四块就出四张；800 字只讲一件事就出一张。
       也别反过来硬凑——**一块就是一块**。
   - **给这一节标出"默认显示"的那张**，把它放在 `views` 数组的**第一位**，加 `"primary": true`
     （其余图**不加**这个字段；要写就写 `false`）。**用户不点 tab 时看到的就是它**：
     * **多块的长节** → **概览概念网**当 primary。用户要先看到全貌，再自己往下钻；
       一上来就给某一块的流程图，用户会以为这节只讲那件事。
     * **只有一块的短节** → 内容上最贴的那张：讲过程给 `flow`、讲结构给 `domain`、
       讲对比给 `matrix`，**别顺手把概念网顶上去**。
     **一节最多一张 `primary`**——两张就是没想清楚哪张最重要，校验器会拦。
5. **别贪多，而且要听"本节规模"的话**。
   输入里会给你一行「本节规模」——**那是硬上限**（每张图不超过 N 个节点）。
   一般一张图 6–14 个节点最舒服，但**本节只有 6 句话时，就只画 6 个节点**。
   **每个节点都得有一句原文撑着**；句子不够就是不够，宁可少画，绝不许硬凑。

## 二、输出格式（JSON，不要任何解释文字）

```json
{
  "titleZh": "本节标题的中文（**照手工版的规格**：一二级结构 + 这一节的具体内容）",
  "lead": {
    "gist": "这一节在讲什么、得到什么结论（≥30 字，给'读之前'的人看，不是复述标题）",
    "focus": ["读的时候盯住这句：……", "还有这句：……"]
  },
  "views": [ ... 按"意思块"分：只一块就 1 张；多块就「1 张覆盖全节的概览概念网 + 每块 1 张」。
             张数上限见输入里的「本节规模」，但那是兜底不是任务。
             默认显示的那张放第一位，并加 primary: true ... ]
}
```

**`titleZh` 怎么写**（这是顶栏 tab 上给人看的字，要一眼知道这节讲什么）：

| 原节标题 | titleZh |
|---|---|
| `SUMMARY` | `摘要（Summary）` |
| `INTRODUCTION` | `引言（Introduction）` |
| `Development of an Absolute Quantitative MS Method to Cover All CD3 ITAMs` | `结果 · 绝对定量质谱方法（TIMLAQ-MS）` |
| `CD3ε ITAM Recruits the Inhibitory Kinase Csk` | `结果 · CD3ε ITAM 招募抑制性激酶 Csk` |
| `CD3 Phosphorylation Patterns` | `讨论 · CD3 磷酸化格局` |
| `Concluding remarks and future directions` | `结论与展望` |

规则：**摘要/引言**用「中文（英文）」；**结果/讨论小节**用「结果 · 中文」/「讨论 · 中文」；
总起和结尾用「引言」「讨论」「结论与展望」这类词。**总长 ≤ 20 个汉字**，别照抄英文的啰嗦定语。

### 视图 A：concept-map（概念网）

```json
{
  "id": "本节id-概念",
  "type": "concept-map",
  "title": "中文小标题（简短，如'概念网络'）",
  "nodes": [
    { "id": "全局概念id", "label": "显示名", "short": "短名", "zh": "中文名",
      "cluster": "mechanism", "evidence": [{"page": 857, "quote": "原文句"}] }
  ],
  "edges": [
    { "from": "节点id", "to": "节点id", "rel": "促进", "label": "中文关系短语",
      "polarity": "promote", "origin": "sentence", "evidence": [{"page": 857, "quote": "原文句"}] }
  ]
}
```

### 视图 B：flow（流程图）

同上，`"type": "flow"`。**必须无环**（不许 A→B→A，也不许回头边）。

### 视图 C：domain（模式图——蛋白结构域 / CAR 构建体）

```json
{
  "id": "本节id-模式", "type": "domain", "title": "中文小标题",
  "domain": {
    "tracks": [
      { "id": "轨道id", "label": "这条链叫什么", "cluster": "mechanism",
        "evidence": [{"page": 857, "quote": "原文句"}],
        "segments": [
          { "label": "方块名", "kind": "itam", "len": 1, "evidence": [{"page": 857, "quote": "原文句"}] }
        ] }
    ]
  }
}
```
- `kind` 只能是：`plain` `itam` `brs` `prs` `linker` `costim` `kinase` `mutant` `sp` `scfv` `insert` `signal`
- `len` = 相对宽度（正数，拿不准就写 1）

### 视图 D：matrix（对照表——突变体 × 表型）

```json
{
  "id": "本节id-对照", "type": "matrix", "title": "中文小标题",
  "matrix": {
    "cols": [{"id": "cytokine", "label": "细胞因子"}],
    "rows": [
      { "id": "行id", "label": "行名", "cluster": "application",
        "cells": { "cytokine": {"mark": "down", "text": "降低",
                    "evidence": [{"page": 863, "quote": "原文句"}]} } }
    ]
  }
}
```
- **每一行必须给每一列一个格子**；原文没说就写 `{"mark": "na"}`，**不许留空**
- `mark` 只能是：`same`（相当） `up`（升） `down`（降） `none`（没有） `na`（原文没说）

## 三、受控词表（`rel` 只能从这里选，不许自己造词）

结构：`包含` `构成` `定位` `修饰`
因果-正：`促进` `激活` `增强` `诱导` `招募` `上调` `介导` `经由`
因果-负：`抑制` `衰减` `下调` `减弱` `阻断`
证据：`测量` `提示` `支持` `反驳` `总结`
时序：`依赖于` `先于` `随后`
应用：`设计策略` `插入` `突变` `替换`

### ⚠ 最容易踩的：想到什么写什么

你脑子里冒出来的词**十有八九不在表里**。对照下表换掉——**校验器只认表里的字**：

| 你可能会写 | 换成 |
|---|---|
| 结合 / 绑定 / bind / association | `招募`（招来下游分子）或 `依赖于`（以它为前提） |
| 识别 / 感知 / recognize / sense | `招募` 或 `激活`（看语境） |
| 磷酸化 / 去磷酸化 / 泛素化 | `修饰` |
| 转运 / 定位到 / localize / traffic | `定位` |
| 形成 / 组装 / assemble / complex | `构成` |
| 调控 / 调节 / regulate / control | `促进` 或 `抑制`（**必须选一边**；真选不了用 `介导`） |
| 表达 / 分泌 / 产生 / produce / secrete | `上调` 或 `介导` |
| 引起 / 导致 / 使得 / lead to / drive | `诱导` 或 `促进` |
| 参与 / 涉及 / involve / contribute | `介导` |
| 相互作用 / interact / couple | `招募` 或 `依赖于` |
| 降低 / 减少 / reduce | `下调` 或 `减弱` |
| 增强 / 提高 / enhance | `增强`（表里有） |
| 杀伤 / 杀死 / kill / cytotoxicity | `介导` |
| 敲除 / 缺失 / knockout / deficiency | `突变` |
| 过表达 / 回补 / overexpress / rescue | `上调` |
| 逆转 / 恢复 / reverse / restore | `阻断`（如果是否定了某个效应）或 `上调` |
| 竞争 / 取代 / compete / displace | `替换` 或 `抑制` |
| 平衡 / 稳态 / balance / homeostasis | `介导`（或拆成两条 `促进`/`抑制`） |
| 决定 / 支配 / determine / dictate | `介导` 或 `促进` |
| 区分 / 辨别 / discriminate | `依赖于`（若强调靠某机制区分）或 `介导` |

**兜底**：实在找不到最近的就用 `介导`（最中性的一个）。
**绝对不许自己造词**——校验器只认表里那 29 个字，造了整份打回。

**其他字段的取值也必须来自枚举**：
- `cluster` → `mechanism`（机制）/ `application`（应用、工程改造）/ `conclusion`（结论、论点）
- `polarity` → `promote` / `inhibit` / `neutral`
- `origin` → `sentence`（原文明说）/ `structural`（结构关系，可补全）/ `inferred`（要额外假设，慎用）

## 四、节点 id 要用**全局概念 id**（跨论文能接上的那种）

命名法：小写、点分、英文。例：`cd3e.itam`、`csk`、`lck`、`tcr.signaling`、`cd45`、`zap70`、`p85`、`brs`、`itam.phos`、`car.19.28z`

**同一节内多张图复用同一个概念时，id 必须一模一样**——否则"以 X 为中心查看"就断了。

## 五、给你的输入

下面会给你：
1. **本节标题与页码**
2. **本节原文**（带 `[第 N 页]` 分页标记）
3. **已有全局概念表**

### ⚠⚠ 关于「已有全局概念表」，最容易犯的错

那张表是**给你统一命名用的，不是给你选概念用的**。它列的是**别的节**用过的概念。

**铁律**：
- 只画**本节原文里真的讨论到**的概念
- **表里有、但本节没提**的概念 → **不许出现在本节图里**。硬拉进来就只能编造引文，
  而编造的引文一定匹配不上原文 → 整份打回重来（实测栽过两次）
- 表里有、本节也提到的 → **用表里那个 id**（别新造 `immunoreceptor2` 这种）

一句话：**先读本节原文决定画什么，再回表里查这些概念叫什么**。顺序反了必错。

### ⚠ 流程图（`flow`）不许成环

`A → B → C → A` 这种回头边一律打回。画流程时**先在心里把箭头顺一遍**：
信息流是单向往前的。如果确实有反馈回路，**拆成两条边**或用 `抑制`/`下调` 反过来画，
不要真的连一条回到起点的箭头。

现在开始。**只输出 JSON，不要 markdown 代码块标记，不要任何解释。**
